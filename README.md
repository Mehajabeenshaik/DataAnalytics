# DataAnalytics — Governed AI Data Analyst Agent

A local-first AI agent that answers natural-language business questions against your
own data — static or live — without ever letting an LLM write raw SQL, touch your
database directly, or see unmasked customer PII.

This is the **backend/agent** half of the project. A separate frontend (built
independently) talks to this agent through one stable function call:
`agent_phase2.ask(question, source, provider)`.

---

## Why this exists

Most "chat with your data" tools let an LLM generate SQL directly against your schema.
That's fast to build and unreliable in practice — on messy, real-world schemas, raw
text-to-SQL accuracy drops sharply, and a wrong answer looks exactly as confident as a
right one.

This project takes a different approach: the LLM never writes SQL. It only **selects**
from a small, predefined, human-reviewable catalog of metrics and statistical tools.
All query execution is deterministic Python/SQL, generated by code — not by the model.

---

## Architecture

```
Question in
     │
     ▼
┌───────────────────────────────────────────────────────────┐
│  agent_phase2.py — plan → execute → synthesize              │
│                                                             │
│  1. plan()        LLM picks: single_metric | stats_tool |    │
│                    propose_metric | no_match                 │
│                    (never raw SQL — validated against the    │
│                    real catalog; anything else is rejected)   │
│                                                             │
│  2. execute_plan() Deterministic. No LLM call.                │
│                    → agent_core.run_metric()                  │
│                    → stats_tools.run_stats_tool()              │
│                                                             │
│  3. synthesize()   LLM writes a plain-English answer,          │
│                    with confidence + caveat flags               │
└───────────────────────────────────────────────────────────┘
     │
     ▼
{ answer, confidence, caveat, metric_used / tool_used, filters_used }
```

**Supporting layers:**
- `data_source.py` — loads data from a **static snapshot** (CSV / DataFrame / SQLite)
  or a **live connection** (`connect_live()` — see below), auto-profiles it, and
  exposes one unchanged `query()` interface either way
- `metric_factory.py` — auto-generates a safe metric catalog (sum/avg/count/breakdown
  metrics) from the data profile; the LLM only ever sees names + descriptions, never
  raw columns or SQL
- `stats_tools.py` — six deterministic statistics tools (describe, value_counts,
  correlation, group_compare, missingness, trend)
- `cache.py` — TTL-based response cache so repeated questions skip the LLM entirely
- `pii_masker.py` + `encryption.py` — Presidio-based PII detection, masked at load
  time, with a Fernet-encrypted vault for original values
- `llm_provider.py` — pluggable LLM backend: **Ollama (local, default)**, Gemini, or
  NVIDIA NIM — swap via one env var

## Safety guarantees (all covered by tests)

| Guarantee | How |
|---|---|
| No SQL injection | All filters go through parameterized, allowlisted queries — never raw string interpolation |
| No LLM-invented metrics/tools trusted | Every LLM response is validated against the real catalog; anything outside it is rejected, not executed |
| No confident wrong answers | Malformed LLM output, small result sets, or ambiguous questions degrade to `no_match` or `confidence: "low"` — never a silent guess |
| No unmasked PII reaches the LLM | PII is masked at data-load time (Presidio), with a second defense-in-depth scrub before any result is sent to the model |
| No plaintext secrets at rest | PII vault and main DB are Fernet-encrypted; `JWT_SECRET_KEY` refuses to start on an insecure default |
| No writable connections in live mode | `connect_live()` actively rejects a connection string with write access before allowing any query |

## Quick start (local, no API key required)

### 1. Install dependencies
```bash
python -m pip install -r requirements.txt
python -m spacy download en_core_web_sm
```

### 2. Install Ollama and pull the default model
```bash
ollama pull nemotron-3-nano:4b
```

### 3. Configure environment
```bash
cp .env.example .env
```
Generate a real JWT secret and paste it into `.env`:
```bash
python -c "import secrets; print(secrets.token_hex(32))"
```
No LLM API key is needed for local use — `LLM_PROVIDER=ollama` is the default.
**Never commit `.env` or paste its contents anywhere — only `.env.example` (placeholders
only) is safe to share.**

### 4. Try it
```bash
python demo.py
```
```
Question: What is our total revenue?
Answer: Your total revenue is over $121 million
   Metric:    total_revenue
   Confidence: high

Question: What's the weather today?
Answer: I don't have a defined metric that answers this question yet.
```

## Static data vs. live data

`DataSource` supports two modes behind the exact same `query()` interface — nothing
downstream (`agent_core.py`, `agent_phase2.py`, `stats_tools.py`) needs to know which
mode is active.

### Static (default) — snapshot loaded once
```python
source = DataSource(name="my_data")
source.load_file("orders.csv")          # or load_dataframe() / load_sqlite()
```
Data does not change until you reload it. Simple, safe, good for demos and one-off
analysis.

### Live — queries a real database on every question
```python
source = DataSource(name="my_data")
source.connect_live(
    connection_string="postgresql://agent_readonly:***@host/db",  # READ-ONLY role only
    refresh_mode="ttl",       # "ttl" (cached, lighter load) or "always" (always fresh)
    ttl_seconds=30,
)
```
- `connect_live()` **actively refuses** a connection string with write access — it
  attempts a rolled-back write and raises `PermissionError` if it succeeds. This check
  is meaningful for Postgres/MySQL with a real read-only role; **SQLite has no
  role-based permissions and is exempted from this check** — treat SQLite live mode as
  mechanism-testing only, never as a security guarantee.
- `refresh_mode="ttl"` caches query results for `ttl_seconds`; `"always"` never caches.
- Try it: `python demo_realtime.py` — inserts a new row into a live DB mid-run and
  proves the agent's answer changes without any manual reload.

**Before pointing `connect_live()` at anything resembling real business data**, verify
the read-only rejection against a real database with actual roles (Postgres/MySQL) —
see `test_data_source_realtime.py` for the pattern, and confirm it against a genuine
`agent_readonly`-style role, not just SQLite.

## Switching LLM providers

| Provider | `LLM_PROVIDER` value | Needs a key? | Notes |
|---|---|---|---|
| Ollama (local) | `ollama` | No | Default. `OLLAMA_MODEL=nemotron-3-nano:4b` |
| Google Gemini | `gemini` | Yes — `GEMINI_API_KEY` | Free tier at aistudio.google.com |
| NVIDIA NIM | `nvidia` | Yes — `NVIDIA_API_KEY` | Cloud-hosted Nemotron/DeepSeek/Qwen catalog |

Switching providers never requires code changes — only `.env`.

## Evaluation

Accuracy is measured against a real golden question set, run against a live LLM
(not mocks):

```bash
python eval/run_eval.py        # single run
python eval/run_eval_3x.py     # 3 consecutive runs — checks stability, not just a score
```

Always re-run this after changing `metrics.py`/`stats_tools.py` synonyms, switching
models, or adjusting temperature. A model swap that "feels fine" in a few manual
questions can still regress on edge cases — trust the eval number, not vibes.

## Project structure

| File | Purpose |
|---|---|
| `agent_phase2.py` | Top-level agent — plan/execute/synthesize pipeline |
| `agent_core.py` | Metric selection + deterministic metric execution |
| `metric_factory.py` | Auto-generates the metric catalog from a data profile |
| `data_source.py` | Loads/profiles static data; supports live DB connections |
| `stats_tools.py` | Deterministic statistics tools |
| `cache.py` | TTL response cache to skip redundant LLM calls |
| `llm_provider.py` | Ollama / Gemini / NVIDIA NIM provider abstraction |
| `pii_masker.py` | Presidio-based PII masking + encrypted vault |
| `encryption.py` | Fernet encryption wrapper for databases at rest |
| `auth.py` / `auth_middleware.py` | FastAPI JWT auth, admin/viewer RBAC |
| `audit_logger.py` | Audit trail for queries and PII access |
| `session_manager.py` | Thread-safe session expiry |
| `config.py` | All configuration; refuses to start on insecure defaults |
| `demo.py` | Interactive CLI for `agent_phase2.ask()` (static data) |
| `demo_realtime.py` | Proves live-mode data changes are picked up without reload |
| `eval/run_eval.py`, `eval/run_eval_3x.py` | Golden-set accuracy evaluation |

**Databases (`*.db`, `*.db.enc`) are not committed.** They're generated fresh on
first run. Never commit a real `.env` — only `.env.example`.

## For frontend integration

```python
from data_source import DataSource
from agent_phase2 import ask
from llm_provider import get_provider

source = DataSource(name="my_data")
source.load_file("orders.csv")          # or connect_live(...) for live data

provider = get_provider()               # reads LLM_PROVIDER from env
result = ask("What is our total revenue?", source, provider)
```

Returns:
```python
{
    "answer": "Your total revenue is over $121 million",
    "confidence": "high",       # "high" | "low" | "n/a"
    "caveat": None,              # string or None
    "metric_used": "total_revenue",   # or tool_used, or None on no_match
    "filters_used": {"customer_region": "North"}
}
```
`metric_used`/`tool_used` being `None` means the agent explicitly declined to answer
rather than guessing — the frontend should render this as a clear "I don't know" state,
not an error.

## Known limitations

- Single-tenant — one `DataSource` per running instance, not yet multi-customer isolated
- Live mode's read-only enforcement is only verified against SQLite (mechanism-only) —
  confirm it against a real Postgres/MySQL read-only role before using with real data
- No production deployment configuration yet (Docker/hosting) — currently runs locally
- Estimated fields (e.g. profit margin on datasets without real cost data) are
  approximations — check `metric_factory.py`'s generated catalog before treating any
  derived metric as ground truth
